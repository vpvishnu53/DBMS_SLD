LEGEND
  (PK)        key attribute (underlined in the diagram)
  (PPK)       partial key of a weak entity
  [MV]        multivalued attribute (double oval)
  [D]         derived attribute (dashed oval)
  {a, b, c}   composite attribute and its components

#####################################################################
 PART B - THE WEBSITE / ORACLE DATABASE (what was actually built)
#####################################################################

 The ER diagram is mapped to 20 Oracle tables in schema SLMS:
   - 14 tables for the entity sets
   - 5 tables for multivalued attributes
   - 1 junction table for the M:N relationship "uses"

 Mapping rules used:
   * Composite attributes are flattened into plain columns
       Name -> first_name, middle_name, last_name
       Address -> street, city, state, pincode
       location -> latitude, longitude
   * Multivalued attributes get their own child table
   * Derived attributes are NOT stored; they are computed in SQL views
   * 1:N relationships become a foreign key on the "N" side
   * "uses" (M:N) becomes the table WORK_ORDER_PART
   * ENERGY_LOG's primary key is (pole_id, log_number)

 Where each relationship lives in the tables:
   employs       -> EMPLOYEE.dept_id
   logs_into     -> HOMEPAGE.emp_id          (unique)
   registers_on  -> HOMEPAGE.citizen_id      (unique)
   accesses      -> HOMEPAGE.license_no      (unique)
   supervises    -> ZONE.emp_id
   handles       -> COMPLAINT.handled_by
   assigned_to   -> WORK_ORDER.emp_id
   submits       -> COMPLAINT.citizen_id
   executes      -> WORK_ORDER.license_no
   scheduled_in  -> WORK_ORDER.zone_id
   contains      -> FEEDER_PILLAR.zone_id
   located_in    -> STREETLIGHT.zone_id
   deployed_in   -> SENSOR.zone_id
   powers        -> STREETLIGHT.cabinet_id
   has           -> SENSOR.pole_id
   receives      -> COMPLAINT.pole_id
   requires      -> WORK_ORDER.pole_id
   resolves      -> WORK_ORDER.complaint_id
   generates     -> BILLING.work_order_id    (unique)
   uses          -> WORK_ORDER_PART (work_order_id, part_id, quantity_used)
   records       -> ENERGY_LOG.pole_id       (part of its primary key)

 B2. DERIVED ATTRIBUTES (computed in views, never stored)

---------------------------------------------------------------------
 B3. ATTRIBUTES THE WEBSITE ADDED BEYOND THE DIAGRAM
---------------------------------------------------------------------
   HOMEPAGE.user_type        which kind of account: EMPLOYEE / CIVILIAN / COMPANY
   HOMEPAGE.emp_id           links the login to exactly one employee,
   HOMEPAGE.citizen_id       citizen or company (a CHECK allows only one)
   HOMEPAGE.license_no
   HOMEPAGE.is_active        lets an admin disable a login
   HOMEPAGE.created_at       account creation time
   HOMEPAGE.last_login_at    last successful sign-in
   WORK_ORDER_PART.quantity_used   how many of a part a work order used
   SENSOR.pole_id            sensor mounted on a pole (relationship "has")
   Foreign-key columns that implement the relationships (see list above).
   Child tables for the multivalued attributes (EMPLOYEE_EMAIL, etc.).
